method

One file, one direction, then proof

Studio builds one self-contained HTML artifact against a named design direction, renders it at 390 and 1440, scores it, and revises once before handing it over.

  1. Build

    One file. The direction's tokens.css goes into the style block first, and every rule below it is authored against those custom properties.

  2. Render

    The same file at two viewport widths, from disk, with no server involved: 390 by 844, then 1440 by 900.

  3. Score

    Out of 100. The direction's own avoid list carries 60 of those points, which is why a generic entry on that list is a wasted slot.

  4. Revise

    Once. If the second run still fails, the file ships with its score and every failing check named out loud.

registry

Four directions

Every direction answers the same 35 custom properties in the same order, so the artifact changes completely when one tokens.css is swapped for another and nothing else moves.

Direction Ground Character Suits
editorial light paper two families, no negative tracking, almost no radius long reads, essays, explainers, reports

product-dark near-black alpha-tint elevation, white-alpha hairlines, tight tracking developer tools, dashboards-as-marketing
calm warm off-white one family, large flat colour fields, large radii consumer, wellbeing, onboarding, anything friendly

Each direction's DESIGN.md names the page it is measured against. This one is measured against Ramp's pricing page, which is where the white ground, the single accent and the zero shadow come from.

type

Font policy

  • A blacklist, not a whitelist. Twenty families are refused by name; anything not on that list is available.
  • Inter is body and UI only, never display. Inter at 72px in a hero is the loudest signal that an agent made the page.
  • One or two families per artifact, never three. This direction uses one grotesque, with a mono for labels and literals.
  • Display weight stays light. Across the measured references it runs 300 to 510, and the h1 above is 400.

Asked once, before any markup exists:

Free fonts (safe to share) or your licensed set (this machine only)?

--radius-sm rounds the table container and inline code, --radius-md every button and CTA, --radius-lg a detached card or panel, and --radius-pill small mono badges only — the tile above is 32px tall for that reason, since 9999px on a 44px control produces a capsule that belongs to a consumer app. Zero is always available and is not a violation of the scale: the lattice takes no radius at all, because two adjacent rounded corners cannot share one line.

specimen — elevation

Elevation

Four surfaces, one of them raised: judge whether a line reads as depth without a single blurred pixel to help it.

--ground · the sheet everything sits on. No fill of its own and no border.
transparent fill + 1px solid --hair · the only raised state there is.
--ground-2 · first sunk level: code blocks, the footer strip, a pressed control.
--ground-3 · deepest sunk level: the table header row, inline code, a control mid-press.

Every tile above declares box-shadow: var(--shadow-1) and none of them draws one, because --shadow-1 is none — kept in the vocabulary so a consumer can write the property and get nothing back, and so swapping in another direction's tokens leaves no dangling variable. Depth runs downward instead of upward: a raised surface takes a hairline and never a fill, a sunk surface takes a fill and never a border, so the two signals cannot be confused.

Hero

Section head, lead and note

surface ladder

Elevation is a line, not a blur

There is exactly one raised state and it is signalled by the presence of a hairline: a transparent fill with 1px solid --hair around it, and nothing else.

There is no second raised level, because a second level would need a second signal and the only one left is a shadow.

Grid and panels

Use it for

Pricing tables, plan comparisons, spec sheets, changelogs, API overviews and technical product pages.

Not for a long read

The white ground, the 16px body and the generous card insets are tuned for scanning, not for forty minutes of prose. The editorial direction exists for that.

Not for an emotional subject

A page whose only decoration is a ruled line reads as cold on purpose. The calm direction exists for that.

Not for a dark surface

Inverting this direction means re-deriving the whole ladder, which is what product-dark already is.

Features, two of them

Cards share their borders

Put the top and left hairline on the grid container and the right and bottom hairline on each cell: no doubling anywhere, one continuous rule, and it reflows to a single column on a phone without a line going missing.

The cell count fills the row

Five items in a three-across lattice leave a half row, and the empty slot has no cell to carry the right and bottom hairline. Change the column count so the grid divides evenly, or emit an empty cell with the same borders and no content.

List and steps

Where the accent is allowed, and nowhere else:

  • The primary button, as a fill with an --ink border the secondary lacks.
  • A small mono badge, at --radius-pill and nothing taller.
  • The text selection highlight, with --accent-ink on top of it.

  1. Change the column count

    Five items go five-across, or reflow to a list, so the grid divides evenly and the bottom edge closes.

  2. Or emit an empty cell

    It carries the same right and bottom hairline and no content. A lattice with a half-drawn bottom edge reads as a rendering fault.

Badge, figure and call to action

tabular-nums Every table, stat and price sets it, because Schibsted Grotesk's default figures are proportional and a column of prices will not align down its own decimal.
