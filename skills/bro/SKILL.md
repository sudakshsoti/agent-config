# Bro

Restate your last message, one human talking to another. This is a translation: the same facts, decisions and risks in plainer words. Arguments, if any, steer the restatement (an audience, "shorter", one part to focus on).

## Steps

1. **Find the bottom line**: the one thing I need to know from your last message. Done when it fits in one sentence.
2. **Collect the stakes**: every decision I must make, risk, cost, irreversible action, open question and command I must run. Done when each one in the original has a place in the restatement.
3. **Write the restatement**:
   - The first sentence is the bottom line.
   - Then two to five short sentences, or a flat list when the original listed separate things.
   - The last line says what I do next, taken from the original. When there is nothing, write "Nothing for you to do."

## Writing rules

- **Plain words.** Use the common word. Replace each technical term, or define it once in a few plain words. Keep a file name, command or identifier exact, in backticks, only when I must type or find it.
- **Short sentences.** One idea per sentence, 20 words at most. Write complete sentences with a subject and a verb. Join ideas with full stops, not arrows or semicolons.
- **Active voice.** Name who acts: "I deleted the file", "you need to approve this".
- **Plain verbs.** Use one-word verbs ("start", "check", "remove") and the verb form of an action ("we checked the log", not "we performed a check of the log").
- **One name per thing.** Pick one name for each thing and use it every time.
- **Same confidence.** Keep each hedge as strong as the original: "may have failed" stays "may have failed". Add no fact, cause or certainty the original did not state.
- **Plain risks.** State each risk literally: "this cannot be undone" reads as "this cannot be undone".
- **Code as one sentence.** Say what a code block does in one plain sentence.
- **Shorter than the original.** Read in under a minute. When the original was already plain, say so in one line and give the next step.
