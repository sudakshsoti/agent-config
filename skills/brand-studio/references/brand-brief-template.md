# Brand brief template

Copy this file into the working repo or notes for the engagement and fill it there. Do not
edit it in place — this copy stays blank so the next engagement starts clean. One brief per
brand; swap the whole thing when the brand changes.

This is the descriptive layer: what the brand **is**, as a matter of fact. It carries no
diagnosis and no recommendation. The argument about what is wrong and what to do lives in the
conversation and in the Decisions log at the foot. Keep the brief stable: update it when a fact
changes or gets confirmed, not when an opinion shifts.

Where a section does not apply, delete it rather than leave it blank.

**Confidence flags.** Mark verified lines `[confirmed]` (checked against data, filings, or the
live product) and working assumptions `[unconfirmed]`. Never treat an unconfirmed item as
settled, and say so when the reasoning leans on one.

## What this brand is, in one line

> _[Brand name] ([domain]) is a [category] brand selling [what] to [whom], via [channels]. The
> engagement is [scope of this piece of work]._

## The working relationship

Plain facts about who the work is with and how, so the reasoning has context. No behavioural
rules here. Record only what is true:

- **Who:** founders / client / own project. Names and roles.
- **Basis:** how this work is set up (paid, unpaid, equity, internal) and the boundaries of scope.
- **What is on and off the table:** the scope line for this engagement, and anything ruled out.
- **Key dates:** discovery call, launch, review gates.

## The offer

- **What they sell, and the spine of it:** the core product or service, the material or
  mechanism it rests on, the honest claim underneath.
- **Range shape:** where the catalogue is broad versus where the revenue actually concentrates.
  Name the hero SKU or hero service if there is one.
- **Price bands:** real selling prices, not list prices.

## Protected assets

Sacred — do not redraw. List the existing assets that are off the table for redesign: a strong
wordmark, a known colour, a founder's name. Refresh around them unless the founders explicitly
open them. Treat any instinct to "modernise" a protected asset as out of scope.

## Known unknowns

The facts that would change the argument if resolved. Each is a question to close at the
discovery call or by pulling data. Promote them into the tables above, marked `[confirmed]`,
once answered.

## Anchor set

The references for this engagement: keystone, direction, ceiling, anti-references. Structure and
how to build it are in `taste-and-exemplars.md`.

# Decisions log

Meaningful calls, settled, in a form that survives across sessions so the work does not
contradict itself. One line each: the decision, the date, and the trade-off it accepts.

- _[YYYY-MM-DD] Decision. The trade-off it accepts._

For a call big enough to need alternatives and a revisit trigger recorded, write the full entry
using the "Design decision log entry" format in
`design-foil/references/templates-and-prompts.md`, and keep the one-liner here as the index.
