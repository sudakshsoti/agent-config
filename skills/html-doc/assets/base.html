This document is the template the html-doc skill copies. It uses every primitive in the vocabulary exactly once and explains, beside each one, the case it exists to handle. However this page looks in your browser is how every document the skill produces will look.

What this file is

The skill has one job: turn markdown into a single self-contained HTML file. The failure mode it exists to prevent is a document request being treated as a web-design request — a fresh palette, a hero heading and a card grid invented from scratch on every invocation, so no two outputs match. Shipping a working template instead of prose about CSS is what makes the output deterministic.

Nothing here loads over the network. Fonts come from the system stack,1 there is no JavaScript, and the whole stylesheet sits in one <style> block in the head. The file works offline, from a USB stick, and in five years.

Key takeaways

  • Copy this file, delete the CSS for primitives you did not use, and fill in content.
  • Do not author new CSS. Needing a new selector means the content wants a shape the vocabulary lacks — say so instead of inventing one.
  • Visual complexity follows informational complexity. A 400-word note gets a header and prose, nothing else.
  • A theme swap is one :root block. Nothing below it holds a literal colour or spacing value.

The token block

Every rule in the stylesheet reads a custom property. That is load-bearing rather than tidy: alternate themes ship as drop-in :root blocks, so a single literal colour anywhere further down would survive the swap and break the theme.

:root {
  color-scheme: light dark;

  --paper: #faf9f7;   /* page background        */
  --ink:   #22201d;   /* body text              */
  --muted: #6b6660;   /* meta, captions, labels */
  --rule:  #e2ded6;   /* hairlines and borders  */
  --fill:  #f1efea;   /* code, table head, bars */
  --accent:      #33417a;
  --accent-soft: #e7e8f1;
}

The token names below are the whole set. Adding one is a change to the skill, not to a document.

--paper / --ink / --muted
Background, body text, and de-emphasised text. Neither mode uses pure black or white; the dark neutrals are tinted toward the accent hue.
--rule / --fill / --accent / --accent-soft
Hairline borders, flat surfaces, the one accent, and its tinted background.
--font-body / --font-ui / --font-mono
Serif for reading, sans for metadata and labels, mono for code and figures. All three are system stacks.
--measure / --wide / --leading
Reading column (68ch), full page width, and line height. The measure caps the prose column; the page can be wider to hold the sidebar.
--s1 … --s6 / --radius
The spacing scale and the single corner radius. Nothing below :root writes a margin or padding outside this scale.

Prose primitives

Lead paragraph

The opening paragraph, set larger and muted, appears once at the top of this document. It states what the document is and who it is for in two or three sentences. Use exactly one per file; a second one reads as a subheading and stops working.

Blockquote

For quoted source material — never for emphasis of your own prose. If the quote has an author or a document, cite it.

Where colour is used to convey information, that information must also be available without colour. Paraphrasing WCAG success criterion 1.4.1, Use of Color

Footnotes

For an aside that would derail the sentence but that a careful reader wants. A footnote marker is a superscript link to an item at the bottom of the document, and every item links back to its marker.2 Keep them rare; three or four in a document is plenty.

Callouts and summaries

Two primitives pull something out of the flow. The summary box collects what a reader should retain from the whole document and belongs near the top. Callouts interrupt at the point where the caution or the recommendation actually applies.

Each callout carries a text label as well as a border treatment, so the three kinds stay distinguishable in greyscale printing and for readers who cannot separate the hues. Colour alone is never the signal.

Note

Neutral context a reader can skip without losing the thread. If skipping it would cost them something, it belongs in the body text instead.

Warning

A consequence that is hard to undo. Reserve this for real risk — a callout used for ordinary emphasis trains readers to ignore the next one.

Recommendation

The action to take, stated as an imperative. One recommendation per callout, so it can be acted on without re-reading.

Data primitives

Key/value list

A definition list handles short paired facts — parameters, fields, glossary entries — where a table would waste a column on a header nobody needs. The token reference above is one. Prefer it over a two-column table.

Tables

For anything genuinely tabular. Every table sits inside a .table-wrap wrapper that scrolls horizontally, because a wide table is the most common cause of a document overflowing a phone screen.

Procedure and code

Numbered steps

An ordered list for anything a reader will follow while doing something else. One bounded action per step, and the step says what is true when it is done.

  1. Read this file and keep its <style> block whole.
  2. Delete the CSS rules for primitives the document does not use, and delete their demo markup.
  3. Write the content into the remaining structure, preserving the source's code, links, numbers and names byte-for-byte.
  4. Run the validator, fix what it reports, and re-run at most twice before shipping and naming the failing check.

Code blocks

A pre > code pair, scrolling horizontally rather than pushing the page wide. Code is copied from the source exactly; reflowing it to fit a column is a rewrite. Inline code is for identifiers and paths inside a sentence.

This paragraph carries .no-print, so it disappears in print preview along with the table of contents — try Cmd+P.

Navigation and disclosure

The table of contents is a sticky sidebar above 62rem of viewport width and a static block above the text below it. It earns its place past roughly six sections; on a shorter document it is furniture. It is hidden in print, where page numbers and the eye do the same job.

An appendix collapses material that most readers will skip but some will need — raw output, a long list, the workings behind a number. It is a native <details> element, which is why this document needs no JavaScript.

Appendix — why the vocabulary is closed

An open vocabulary means every invocation re-decides what a callout looks like, and two documents produced a week apart stop matching. A closed set of fifteen makes the output boring in the specific way that documents should be boring: the reader learns the shapes once and stops noticing them.

Fifteen is also small enough to hold in view. When content genuinely does not fit any of them, the correct move is to say so in the hand-off rather than to add a sixteenth quietly.

Print and dark mode

Both are handled by overriding the same token names, never by rewriting rules. The print block flattens the palette to a white page with grey rules, drops the grid so the prose uses the full paper width, and prevents tables, code blocks, quotes, callouts and stats from splitting across a page break. Headings will not print as the last line of a page.

Print also reveals link targets: every external link gets its URL appended in parentheses, since a printed page cannot be clicked. Internal anchors and footnote back-links are exempt — printing (#fn-1) after every marker is noise.

Dark mode follows the reader's system setting through prefers-color-scheme. Neither mode uses pure black or white; the dark neutrals carry a trace of the accent hue so the page reads as one surface rather than as a light document with its colours reversed.

What the template deliberately does not have: a card around every section, gradients of any kind, an oversized hero heading, decorative pills, alternating colour bands, repeated identical card grids, centred body text, and icons that carry no information. Each of those makes a document look like a landing page, and a landing page is the wrong register for something a reader is meant to work through and print.
