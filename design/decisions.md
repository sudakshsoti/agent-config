# Pi visual decisions

- [stated] Pi should feel more like the existing Kohra theme. — “can we make it more kohra theme like”
- [stated] Replace Pi’s current overall colour treatment. — “I really don't like the colours of pi overall”
- [stated] Use Kohra’s cool fog foundation rather than Flexoki’s warm black: #141719-style charcoal surfaces with fog-grey text.
- [stated] Keep a muted multicolour working palette rather than reducing the interface to one accent hue.
- [stated] Tool calls and message blocks use neutral charcoal surfaces; status belongs in titles and borders rather than large colour fills.
- [stated] Keep the powerline footer, but simplify it to model, thinking, path, context, and subagent status with fewer separators.
- [stated] Mist blue (#78accf) carries focus, links, selected items, and the active editor border.
- [stated] Thinking levels use a cool-to-warm progression: grey, blue, teal, violet, amber, then red; remove the rainbow effect.
- [stated] Syntax follows Kohra ANSI roles: keywords blue, strings green, numbers violet, functions amber, and types teal.
- [stated] The simplified footer separates segments with centred dots rather than chevrons.
- [stated] Use three subtle surface steps: #1b1e20 for messages, #202427 for tools, and blue-grey #0a3149 for selections.
- [stated] Footer hierarchy uses semantic accents: model grey, thinking dynamic, path blue, context fog, and subagent violet.
- [stated] User and extension messages use nearby neutral surfaces; extension labels use mist blue.
- [stated] Switch Ghostty from kohra-flexoki to kohra-ghostty so the terminal root and Pi share the cool #141719 foundation. This supersedes the earlier Pi-only scope.
- [stated] Keep pi-powerline-footer’s neon welcome splash despite its deliberate contrast with the Kohra working interface.
