# Add frontend-artifact as a shared design skill

Approved 2026-09-12.
Keep Vibe as the workflow; frontend-artifact provides selectable design guidance.
Reuse design-typography, design-interface and design-visual-system rather than creating a parallel design system.

## Implementation

1. Add a compact skills/frontend-artifact entry point and eight progressively loaded language profiles: precision-software, technical-field-guide, editorial-modernist, swiss-graphic, visual-essay, industrial-instrument, quiet-catalogue and personal-software. Include concrete defaults, distinguishing features, variation and visible rejection criteria.
2. Route standalone browser artifacts through the skill, fix the stale design route, and make only small global approval/routing additions. Classify job, audience, frequency, reading mode and narrowest viewport first. An unnamed direction requires recommendation and confirmation; a named direction approves visual defaults without authorising feature or content changes.
3. Curate one inspected screenshot per language with source URL, capture date and specific borrow/avoid notes. Reuse installed Pi Playwright and Chromium. Codex inspects images with view_image; Pi attaches images to a model with verified image capability.
4. Build with semantic HTML, plain CSS and minimal JavaScript unless the existing project uses another stack. Render, inspect, correct and re-render, with at most two correction passes and explicit reporting of remaining failures.
5. Install from the canonical agent-config checkout into the shared ~/.agents/skills root. Preserve personal defaults and Vibe. Generate required ZIPs using the approved narrow AGENTS.md exception. Commit and push each completed non-trivial task; do not merge or open a PR.

## Validation

Run three identical briefs in Codex and Pi: streaming latency as technical-field-guide, the same latency content as visual-essay, and a research-list utility as personal-software.
Use Luna high through per-run settings after verifying availability and image support.
Inspect each result at 390 px and 1440 px widths, plus any additional viewport required by the reused design guidance.
Require readable text, working interactions, no unintended overflow, keyboard behaviour and visibly different explainer treatments.

Check named-language approval, unnamed-language confirmation, conflicts with project decisions and reporting when image inspection is unavailable.
Verify packaged reference files open through installed paths in both harnesses and run repository skill and ZIP checks.
The five other languages receive profile and reference review, not generated-output validation, in v1.

## Accepted defaults

Selecting a profile approves its documented defaults and routine choices within them.
Accessibility, applicable stated decisions and the artifact's job take precedence.
The reference library starts at one screenshot per language.
Use the existing installer and browser tools; do not add a framework or duplicate typography guidance.
